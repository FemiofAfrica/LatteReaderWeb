# Public local narrator: what we serve, how it is verified, what is still open

This page records the hosting slice that makes the pinned local narrator
publishable: the model and runtime served as our own static assets under the
25 MiB per-file host limit, the client-side reassembly and hash checks, the
explicit opt-in in the production build, and the measured evidence.

It does not change the speech component, its notices or its source offer; those
are described in `docs/local-narrator-notices.md` and shipped under
`public/voice/`. The private device trial is described in
`docs/private-narrator-trial.md` and still runs.

## 1. What is served

to `/voice/narrator/` unless they start with `/voice/`.

The graph is 41,384,970 bytes, above the host's 26,214,400-byte per-file limit,
so it is written as exactly two parts of 20,692,485 bytes. The whole-file
SHA-256 is `95481626fee1ba70ce683e69c534fc7cb38433c46ce42d3abbeafb4b9f1a4123`
(Kitten Micro 0.8 at revision `1ccf72b2c2048fd17efac7de2fab32d10e225084`).

The voice is the **derived** tensor, not the voicepack: `jasper.f32` is Jasper
(`expr-voice-2-m`) selected from `voices.npz` (3,278,902 bytes, SHA-256
`112710c1be8ad0e967c190fb0fd95cbe5848ec4791b93209f20b28b7da20dac1`), written
unchanged as little-endian float32, 400 × 256 — 409,600 bytes instead of
3,278,902, with no arithmetic, transpose or quantisation. Its derivation is
recorded in the manifest so the smaller shipped file cannot be mistaken for an
independently sourced voice.

**Runtime choice.** ONNX Runtime Web 1.24.3 (MIT), served from our own origin,
never a CDN: `ort-wasm-simd-threaded` (WASM + SIMD, run single-threaded at
`numThreads = 1`, `proxy = false`). The alternatives were rejected on the
per-file limit and on need: `ort-wasm-simd-threaded.jsep.wasm` is 25,014,754
bytes (fits, barely) and `ort-wasm-simd-threaded.asyncify.wasm` is 27,190,919
bytes, over the limit; this narrator runs one CPU inference, so neither WebGPU
nor asyncify is used. The pinned WebAssembly bytes are read from our origin and
handed to the runtime as `wasmBinary`, so the runtime does not fetch a second
copy.

## 2. What a first opt-in downloads

Total: **55,642,054 bytes (53.1 MB)** — 41,384,970 bytes of graph, 409,600 bytes
of voice, 12,435,016 bytes of runtime, and 1,412,468 bytes of the eSpeak-NG
component. The exact list, with a reason for each entry, is
`public/voice/narrator/manifest.json` under `transfer`, and the panel shows that
total before consent rather than only the graph size. The app's own worker
script (`/assets/narrator.worker-*.js`, about 7.4 kB) is fetched at the same
moment and is not part of that number.

Assets are regenerated by:

```sh
npm run narrator:stage            # reads the approved feasibility directory, writes public/voice/narrator/ and the pins
npm test                          # narratorAssets.test.ts re-hashes every shipped file against the pins
```

`scripts/stage-narrator-assets.mjs` refuses to write a manifest whose bytes do
not match the pinned SHA-256 values, and reads every file back after writing.

## 3. How the client verifies, and how it fails

`src/speech/local/assetIntegrity.ts` is the same rule the pinned eSpeak-NG
loader already applies to the speech component — fetch, check the length, check
the SHA-256 — extended to a file that arrives in parts:

- parts are fetched one at a time in the recorded order, so a part cannot be
  placed at the wrong offset;
- the assembled buffer's whole-file SHA-256 is checked before the runtime is
  handed it;
- any missing, short, altered or misordered set raises `ASSET_UNAVAILABLE`,
  `SIZE_MISMATCH`, `HASH_MISMATCH` or `PART_ORDER` and nothing is returned.

`src/workers/narrator.worker.ts` turns that into a fixed reason code, the engine
reports `Local voice failed. Retry or use Browser default.`, and browser speech
is untouched. The whole-file check is the final gate: a part that hashes
correctly but does not belong to the pinned graph is caught there, which the unit
tests exercise directly. In the browser a tampered part is caught by the part
check first.

## 4. Opt-in behaviour in the production build

- Browser speech is the default engine and is unaffected.
- Opening the page and choosing **Local narrator (Jasper)** makes **no request**
  of any kind: the notices, the licence links the source offer and the byte
  total all come from the pins bundled at build time.
- Only **Enable local narrator** starts the download and the worker. No
  prefetch, no hover download, no background retry.
- The private preview still works: with `window.__LATTE_PRIVATE_NARRATOR__` set
  by `scripts/private-narrator-preview.mjs`, the same engine loads the trial's
  worker and its out-of-repository assets instead of the public ones.
- Privacy: the only network activity is GET requests for those static files
  from our own origin. No document text, filename, selection or audio is sent
  anywhere, and the application has no backend.

## 5. Measured evidence

Recorded by `npm run test:narrator` (headless Chromium 156, 2 vCPU Linux host,
built `dist` on a loopback preview, owned `tests/fixtures/reading-quality.pdf`),
written to `.runtime/narrator-public-evidence/`. Audio files produced by the run
are in the same directory.

| Check | Result |
|---|---|
| Requests before Enable (page load, then engine choice) | 0 voice requests |
| Cold opt-in to ready | 5.4 s (worker init 4.98 s) |
| Payload received by the browser | 55,642,054 bytes, equal to the advertised total |
| Every received asset against its pin | 12/12 match, including both 20,692,485-byte parts |
| Bytes the browser received, reassembled | SHA-256 `95481626…f1a4123`, the pinned graph |
| Graph hash the worker verified before use | `95481626…f1a4123`, reported by the worker |
| Audio | 2 chunks synthesised and played, 11.25 s, `AudioContext` state `running`, clock advanced to 14.84 s |
| Played PCM | non-silent, RMS 0.105 on the first 8.875 s buffer |
| Source coverage | the two generated slices join to the fixture text exactly, no truncation |
| Tampered part (content altered, same length) | fails closed `HASH_MISMATCH`, no audio, no inference, plain error shown |
| Truncated part (1,024 bytes short) | fails closed `SIZE_MISMATCH` after the first part only, no second part fetched, no audio |
| Reader after a failure | still starts a browser-speech run (utterance submitted; headless Chromium has no installed voice, so audibility is not claimed) |
| Requests | 38, all to the preview origin, 0 external, 0 with a body, 0 carrying document text or the filename |

**Reload.** The app implements no persistent voice cache, and the test says so:
after a reload the app requests all 12 assets again and every one is answered
`200` with its full body, with no `304` and no reused body. So on this preview a
reload costs the transfer again; nothing here claims caching the app does not
implement. (The routed measurement in the same run shows the same re-request
set; that measurement is not used to claim HTTP-cache behaviour, because
interception can satisfy a request without the browser's cache.)

**Observation, not a regression introduced here:** the pinned eSpeak-NG loader
fetches `espeakng.worker.wasm` twice (371,333 bytes each). That predates this
slice, its component is unchanged by it, and the advertised total counts the file
once.

## 6. Still open before this is published

1. **Notices index.** `public/voice/notices/README.md` §2 still describes the
   Kitten Micro model, `jasper.f32` and onnxruntime-web as staged outside the
   repository for the private trial and "not redistributed by this repository".
   Once these assets are deployed that sentence becomes false and the three
   components belong in §1. The notice files themselves, the modification record
   and the GPLv3 §6(d) source offer are untouched by this slice, and the pinned
   files they describe still hash to the values recorded there.
2. **Licence position for the model and voice.** The publisher's Apache-2.0
   declaration is still unconfirmed in writing and the provenance of
   `voices.npz` is undocumented. Staging the derived tensor in the repository is
   what makes publication possible, not what settles that.
3. **GPLv3 §5(c) combined-work question** for the narrator worker remains with a
   lawyer, as `docs/local-narrator-notices.md` says.
4. **Deployment.** Nothing was pushed or deployed. The Cloudflare Pages
   build copies `public/` into `dist/`; the largest file we ship is 20,692,485
   bytes, under the 26,214,400-byte limit. The production HTML still carries no
   private diagnostics marker.
5. **Device acceptance.** This evidence is one headless Chromium on a 2 vCPU
   Linux host. Physical Mac, iPhone and Android foreground audibility and the
   20-minute sustained run remain unmeasured, as
   `docs/local-narrator-device-results.md` records.
