# Public local narrator: what we serve, how it is verified, what is still open

This page records the hosting slice that prepares a candidate local narrator build: the model and runtime served as our own static assets under the
25 MiB per-file host limit, the client-side reassembly and hash checks, the
explicit opt-in in the production build, and the measured evidence.

The pinned speech binaries and source archive are unchanged. The bootstrap now
reuses verified WASM via the supported `instantiateWasm` hook, not an ignored
`Module.wasmBinary` property. The notices now describe candidate-bundled assets.
The component and source offer are described in `docs/local-narrator-notices.md` and shipped under
`public/voice/`. The private device trial is described in
`docs/private-narrator-trial.md` and still runs.

The graph is 41,384,970 bytes, above the host's 26,214,400-byte per-file limit,
so it is written as exactly two parts of 20,692,485 bytes. The whole-file
SHA-256 is `95481626fee1ba70ce683e69c534fc7cb38433c46ce42d3abbeafb4b9f1a4123`
(Kitten Micro 0.8 at revision `1ccf72b2c2048fd17efac7de2fab32d10e225084`).

The voice is the **derived** tensor, not the voicepack: `jasper.f32` is Jasper
(`expr-voice-2-m`) selected from `voices.npz` (3,278,902 bytes, SHA-256
`112710c1be8ad0e967c190fb0fd95cbe5848ec4791b93209f20b28b7da20dac1`), written
unchanged as little-endian float32, 400 × 256 — 409,600 bytes instead of
3,278,902, with no arithmetic, transpose or quantisation. Its derivation is
recorded in the manifest so the smaller shipped file cannot be mistaken for an
independently sourced voice.

**Runtime choice.** ONNX Runtime Web 1.24.3 (MIT), served from our own origin,
never a CDN: `ort-wasm-simd-threaded` (WASM + SIMD, run single-threaded at
`numThreads = 1`, `proxy = false`). The alternatives were rejected on the
per-file limit and on need: `ort-wasm-simd-threaded.jsep.wasm` is 25,014,754
bytes (fits, barely) and `ort-wasm-simd-threaded.asyncify.wasm` is 27,190,919
bytes, over the limit; this narrator runs one CPU inference, so neither WebGPU
nor asyncify is used. The pinned WebAssembly bytes are read from our origin and
handed to the runtime as `wasmBinary`, so the runtime does not fetch a second
copy.

## 2. Component payload, app code, and actual transfer

The uncompressed component file total is **55,642,544 bytes (about 53.1 MB)**.
This counts one copy of each entry under `transfer` in the manifest, including
our 3,220-byte eSpeak bootstrap. It is not measured network traffic or a
once-only download. The built app worker is additional: this build serves
`/assets/narrator.worker-eiNaGets.js` at 7,475 uncompressed bytes. HTTP headers,
compression, cache revalidation and retries can change actual transfer.
The panel makes these distinctions before consent; the app maintains no
persistent voice cache of its own.

Assets are regenerated by:

```sh
npm run narrator:stage            # reads the approved feasibility directory, writes public/voice/narrator/ and the pins
npm test                          # narratorAssets.test.ts re-hashes every shipped file against the pins
```

`scripts/stage-narrator-assets.mjs` refuses to write a manifest whose bytes do
not match the pinned SHA-256 values, and reads every file back after writing.

## 3. How the client verifies, and how it fails

`src/speech/local/assetIntegrity.ts` is the same rule the pinned eSpeak-NG
loader already applies to the speech component — fetch, check the length, check
the SHA-256 — extended to a file that arrives in parts:

- parts are fetched one at a time in the recorded order, so a part cannot be
  placed at the wrong offset;
- the assembled buffer's whole-file SHA-256 is checked before the runtime is
  handed it;
- any missing, short, altered or misordered set raises `ASSET_UNAVAILABLE`,
  `SIZE_MISMATCH`, `HASH_MISMATCH` or `PART_ORDER` and nothing is returned.

`src/workers/narrator.worker.ts` turns that into a fixed reason code, the engine
reports `Local voice failed. Retry or use Browser default.`, and browser speech
is untouched. The whole-file check is the final gate: a part that hashes
correctly but does not belong to the pinned graph is caught there, which the unit
tests exercise directly. In the browser a tampered part is caught by the part
check first.

## 4. Opt-in behaviour in the production build

- Browser speech is the default engine and is unaffected.
- Opening the page and choosing **Local narrator (Jasper)** makes **no voice request**: the notices, the licence links the source offer and the byte
  total all come from the pins bundled at build time.
- Only **Enable local narrator** starts the download and the worker. No
  prefetch, no hover download, no background retry.
- The private preview still works: with `window.__LATTE_PRIVATE_NARRATOR__` set
  by `scripts/private-narrator-preview.mjs`, the same engine loads the trial's
  worker and its out-of-repository assets instead of the public ones.
- Privacy: the only network activity is GET requests for those static files
  from our own origin. No document text, filename, selection or audio is sent
  anywhere, and the application has no backend.

Real headless Chromium on our own loopback preview at `127.0.0.1:42861`, using
only the owned `tests/fixtures/reading-quality.pdf`. Evidence:
`.runtime/narrator-public-fix-evidence/results.json` and
`.runtime/narrator-component-fix-evidence/component-results.json`.

| Routed cold component bodies | 55,639,324 bytes across 11 responses, each URL counted once by assertion |
| Nested bootstrap outside route visibility | 3,220 bytes **estimated from its file pin**, not measured |
| Component accounting | 55,639,324 observed + 3,220 estimated = 55,642,544 file bytes |
| Additional app worker | 7,475 observed response-body bytes, separate from component payload |
| eSpeak WASM | exactly one 371,333-byte response; verified bytes instantiated without another fetch |
| Graph reassembled from received parts and verified by worker | `95481626fee1ba70ce683e69c534fc7cb38433c46ce42d3abbeafb4b9f1a4123` |
| Component IPA parity | 8/8; 141 mounted voices; all three binary hashes match |
| Integrity failures | corrupted graph: `HASH_MISMATCH`; truncated graph: `SIZE_MISMATCH`; tampered eSpeak manifest: refused |
| Failed graph runs | no inference, no PCM/audio start; browser-speech submission still works |
| Reader PCM pipeline | two generated chunks, 11.25 s of buffers; running Web Audio context and advancing clock; exact fixture source coverage |
| Privacy | 36 observed requests, same origin; 0 external, 0 request bodies, 0 fixture-text/filename leaks; no uncaught page errors |

The former evidence deduplicated URLs and wrongly counted the duplicate eSpeak
WASM once. That claim is superseded: the bootstrap now uses the supported hook,
and both browser suites count repeated requests multiplicatively.

**Transfer/cache evidence is separate.** Routing disables HTTP cache, and the
routed totals above measure decoded response bodies, not network wire bytes.
The suite also records Playwright `request.sizes()` for every component request
in an uninterrupted plain context, cold and after reload. This run reported
46,615,799 encoded body bytes cold and 45,344,439 after reload. The nested worker
bootstrap reported zero cold body bytes despite running, so its transfer size
is not established by that API; these sums are reported API observations, not
complete transfer totals. Header bytes are separate. On reload several small
files report zero body bytes while the two graph parts and runtime WASM still
report body transfer. Playwright can expose a cached/revalidated response as
status 200, so status and Content-Length alone do not establish caching.
No pinned size is substituted into these measured request-size records.

These are short fixture and headless checks, not audible device acceptance,
sustained-reading evidence or legal clearance.

## 6. Still open before this is published

1. **Notices index corrected.** §2 now states that the model, derived voice and
   runtime are bundled in the candidate repository/build, not publicly deployed.
   The pinned generated binaries and GPL corresponding-source archive are unchanged.
2. **Licence position for the model and voice.** The publisher's Apache-2.0
   declaration is still unconfirmed in writing and the provenance of
   `voices.npz` is undocumented. Staging the derived tensor in the repository is
   what makes publication possible, not what settles that.
3. **GPLv3 §5(c) combined-work question** for the narrator worker remains with a
   lawyer, as `docs/local-narrator-notices.md` says.
4. **Deployment.** Nothing was pushed or deployed. The Cloudflare Pages
   build copies `public/` into `dist/`; the largest file we ship is 20,692,485
   bytes, under the 26,214,400-byte limit. The production HTML still carries no
   private diagnostics marker.
5. **Device acceptance.** This evidence is one headless Chromium on a 2 vCPU
   Linux host. Physical Mac, iPhone and Android foreground audibility and the
   20-minute sustained run remain unmeasured, as
   `docs/local-narrator-device-results.md` records.

## Keeping the voice on the device

After the reader presses Download voice, each verified file is stored in Cache Storage under
`latte-narrator-<fingerprint>`, where the fingerprint covers every pinned path, size and SHA-256.
Later visits load the voice from that cache with no network request; bytes read back are verified
again before use. A new model or voice changes the fingerprint, so it downloads once and the old
cache is deleted. After a real download the app calls `navigator.storage.persist()`.

The voice mode (Browser or Natural), the Natural voice id and the reading speed are kept in
localStorage (`latte-voice-preference`). On reload with Natural selected and the files cached, the
voice loads from the device; if the files are gone it never downloads by itself and shows the
Download voice prompt again. Pages serves `/voice/narrator/*` with `max-age=0, must-revalidate`,
which is why the HTTP cache alone was not enough. `scripts/voice-persistence-smoke.mjs` checks all of this.
