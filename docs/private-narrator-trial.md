# Private Kitten Micro browser-reader trial

This is a locally committed experiment, not a public release or a default-engine migration. Native PDFReaderSpeaker and installed app bundles were not modified.

## Running the private reader

Only `scripts/private-narrator-preview.mjs` injects the trial flag. Standard built HTML has no flag and makes no narrator requests. No model, voice or ORT binary is in the repository or `dist`. The eSpeak-NG speech component **is** in the repository and `dist`, deliberately, because we build and serve it ourselves with its licence notices and corresponding source: see `public/voice/` and `docs/local-narrator-notices.md`.

```sh
node scripts/stage-private-narrator.mjs APPROVED_EXISTING_FEASIBILITY_DIRECTORY OUTSIDE_REPOSITORY_DIRECTORY
LATTE_NARRATOR_ASSETS=OUTSIDE_REPOSITORY_DIRECTORY PORT=4187 node scripts/private-narrator-preview.mjs
```

The preview binds IPv4 loopback and checks the loopback Host; only GET/HEAD are accepted. It serves approved existing private assets, never fetches a model or sends text to a service. No new packages or asset downloads were needed. ORT Web 1.24.3, Micro revision `1ccf72b2c2048fd17efac7de2fab32d10e225084`, Jasper 400×256 float32. English phonemes come from our own pinned eSpeak-NG 1.52.0 WebAssembly build served by the app at `/voice/espeak/`, not from the npm `phonemizer` bundle the trial used before; that bundle is no longer staged or loaded (`scripts/stage-private-narrator.mjs` no longer copies it). Stage script verifies model/Jasper hashes and reads back every copied file. Total staged bytes including notices/metadata: 54,258,045, plus the 1,401,401 bytes of eSpeak-NG component the app serves itself. Assets have no persistent application cache; the session can reuse its loaded runtime.

In Voices, choose **Local narrator (test)**, then **Enable local narrator**. Preparation never starts from page load or engine selection. Once ready, press Play separately. **Cancel and release voice** terminates the worker and releases the audio context. Browser default is reversible and engine choice is not persisted. Existing per-character browser assignments are retained but ignored by Jasper.

## Speech component: our own eSpeak-NG build

The trial used to phonemize through the npm package `phonemizer@1.2.1`, whose single `dist/phonemizer.js` embeds a prebuilt eSpeak-NG (asm.js) plus an English slice of `espeak-ng-data` under the package's `Apache-2.0` label, with **no GPL text, no copyright notice, no source offer and no identifiable eSpeak revision**. It has been replaced by a reproducible build of eSpeak-NG at pinned tag `1.52.0` (commit `4870adfa25b1a32b4361592f1be8a40337c58d6c`) that we compile and serve ourselves.

- The component is served as three separate static files from `/voice/espeak/` (`espeakng.worker.js` 125,613 B, `espeakng.worker.wasm` 371,333 B, `espeakng.worker.data` 904,455 B). It is deliberately **not** bundled into the app: it loads as its own file with its own licence and source.
- [`public/voice/espeak/espeakng.bootstrap.js`](../public/voice/espeak/espeakng.bootstrap.js) fetches all three, checks each against `/voice/espeak/build-manifest.json` by length and SHA-256, and starts the module only from those verified bytes; a mismatch refuses to start. [`public/voice/espeak/phonemizer.mjs`](../public/voice/espeak/phonemizer.mjs) gives the narrator worker the same `phonemize(text, lang)` / `listVoices()` surface the npm package had.
- Licence texts are in `public/voice/notices/`, the modification record and the GPLv3 section 6(d) source offer are in `public/voice/source/SOURCE-OFFER.md`, and the corresponding source archive (18,001,299 B, SHA-256 `92a53e…9ca1`, 2,597 files) is served from the same origin as the object code. `src/components/LocalNarratorNotices.tsx` links all three from the narrator panel.
- Pins and hashes live in `public/voice/espeak/build-manifest.json`, generated by `scripts/voice-manifest.mjs` (which refuses to write a manifest whose files do not match the pinned hashes) and re-checked against the shipped bytes by `src/speech/local/assetManifest.test.ts`.
- Whether the worker bundle forms a single combined work with the GPL component under GPLv3 §5(c) is **unresolved** and is with a lawyer. The notices and the source offer do not settle it. See `docs/local-narrator-notices.md`.

## Engine contract

- Genuine dedicated-worker, single-thread ORT WASM synthesis, transferable finite mono 24 kHz PCM. No prerecorded audio substitutes.
- One inference in flight; at most one current and two ready buffers; ready/current PCM budget <=30 seconds. Results over 15 seconds and over-500-token requests are split into exact source slices and regenerated, not truncated. Normal source slices are <=250 UTF-16 units without cutting surrogate pairs. Unknown IPA fails explicitly.
- Style row uses original input code-point length (max 399); duplicate symbol mapping follows the audited source. Curly quotes/apostrophes map to same-length straight characters for the phonemizer; existing mapped PDF normalization remains the source-offset authority. No blanket waveform-tail trim.
- Audio-clock pause retains the sample offset; Resume reuses that buffer. Stop/seek/engine change/document replacement invalidates old inference and audio callbacks. Cancellation during preparation terminates the worker/downloads. Browser speech API behavior is unchanged.
- Source follow highlights the **playing chunk**, not guessed words. Cross-page chunks remain on their start page until completion. Buffering never advances the source. Browsing preserves playback and suspends follow, while explicit seek replaces the run. Selection-only and selection-to-end remain separate reader actions.
- Buffering, readiness and failure are visible. No automatic cloud/browser fallback. Foreground trial only, no background/lock-screen promises, no generated-audio persistence.

Reproduce from repository root:

```sh

LATTE_CDP=http://127.0.0.1:<your own CDP port> LATTE_READER_URL=http://127.0.0.1:4187/ node scripts/private-narrator-benchmark.mjs
LATTE_READER_URL=http://127.0.0.1:<your own preview port>/ node scripts/narrator-component-smoke.mjs
```

**CDP port trap:** `127.0.0.1:9222` on this host is a live SSH reverse forward to the user's own Mac browser, and a local Chromium started with `--remote-debugging-port=9222` binds `[::1]:9222` instead, so `connectOverCDP('http://127.0.0.1:9222')` silently attaches to the user's real, logged-in browser. Start a browser on a port nothing else uses (and bind it to `127.0.0.1` explicitly), confirm the listener's pid and address family with `ss -ltnp`, and check the UA of the endpoint before driving it. The component smoke asserts the private-preview flag, so it refuses to measure a foreign server.

## Component verification on the pinned eSpeak-NG build (this slice)

Measured on this Linux host with Playwright's bundled Chromium 156.0.8078.4 (headless, `X11; Linux x86_64`) against a private loopback preview of the built `dist` on a port of its own. Evidence: `.runtime/narrator-component-evidence/` and `.runtime/narrator-reader-evidence/` (git-excluded).

- The component really loads: `phonemizer.mjs` → `espeakng.bootstrap.js` → `espeakng.worker.js` 125,613 B, `espeakng.worker.wasm` 371,333 B, `espeakng.worker.data` 904,455 B, all fetched from `/voice/espeak/` with HTTP 200, and the **served bytes hash to the manifest values** (checked by re-hashing each response body in the test). The mounted data package lists **141 voices**.
- Browser IPA is **8/8 byte-identical** to the replaced `phonemizer@1.2.1` output for the sentences compared in the build report (`Hello world.`, `The first different coffee is ready.`, `office waffle`, `financial flow`, `A different coffee, first of all.`, `coffee first different office`, `ﬁnancial ﬂow ofﬁce`, `naïve café résumé`), against `tests/fixtures/narrator-ipa-parity.json`.
- Fail-closed: with the manifest's WASM hash replaced by a wrong value, `phonemize` rejects with `HASH_MISMATCH:espeakng.worker.wasm` and the component never starts.
- Notices and offer: the three panel links return 200, and the archive downloads at 18,001,299 B with SHA-256 `92a53e12260ad748cb80131b420ab73a4bc3c589296e6dbabd1195aee29a9ca1` (gzip magic verified). `SOURCE-OFFER.md` states the GPLv3 §6(d) offer.
- A full narrator read still generates and plays: 6 audio-buffer starts in a running `AudioContext`, resume at a retained offset of 1.13 s, 7 generations (0.61–0.68 RTF on 2 cores), the owned reading fixture's exact cross-page slices unchanged, page follow at chunk completion, no generation underruns, no page errors, and `phonemizer/dist` never requested.
- Privacy: 26 requests in the read run, **0 to any origin other than the preview's and 0 carrying a request body or document text**. The "external origin" check compares parsed origins, because the verified eSpeak-NG source is handed to `importScripts` as a `blob:` URL that carries the page's own origin.

## Verification and delivery limits

Build, typecheck, all 136 unit tests, existing real-browser reading, selection, spoken-position, rotary and Map-compatibility/worker-parser checks passed. The general browser smoke initially failed on stale expected labels `playing`/`ready`; baseline `543b316` already displays `Reading`/`Stopped`, so those two assertions were corrected and its full persistence/upload/navigation smoke passed. Browser speech in those existing suites is mocked and does not establish audible speech. The selection npm wrapper could not regenerate its fixture because system Python lacks reportlab; the existing owned fixture was used by the actual selection smoke, which passed. No-mistakes cannot run: repository is not initialized, daemon stopped, and no configured native/ACP review agent is installed. No claim of independent automated review/CI.

Linux service-manager preview `latte-narrator-trial-preview.service` and self-restarting reverse tunnel `latte-narrator-trial-tunnel.service` successfully exposed `http://127.0.0.1:4187/` on the Mac during the measured runs. Remote HTTP and the actual rendered Mac reader were verified then. At final verification the Mac became unreachable: two Tailscale pings timed out, SSH timed out after retry, and CDP refused connection. The final rerun (including the newly added real paused-seek assertion) is therefore blocked; earlier successful Mac inference/playback is preserved, but current Mac reachability and latest-bundle rerender are not claimed. Linux preview remains active. These are **transient** systemd units, not boot-persistent units. Installation of permanent units was approval-blocked and was not retried; durability/restart-kill testing is unverified. Staged permanent-unit files remain under scratch. A verified private runtime copy exists at `/root/.hermes/latte-private-narrator-runtime`, but the current transient preview still points to the earlier scratch feasibility directory. Do not claim the preview survives reboot or scratch pruning. Existing 4176 preview/tunnel were not restarted.

## Go/no-go

The Mac can synthesize this small corpus slightly faster than playback at 1x, and the short reader pipeline keeps up. Startup and first-chunk latency remain too slow for the proposed target; p95 throughput has little margin. No default migration or public release is approved. Before broader support: human Mac audition, >=20-minute foreground pipeline, full-speed distributions, actual process memory/thermal/battery measurements, embedded-browser and physical mobile tests, interruption/recovery checks, and licensing review.

This slice swapped the narrator's phonemizer onto our own pinned eSpeak-NG build and shipped the licence notices and a reachable corresponding-source offer, so the GPLv3 obligation that the replaced bundle could not satisfy (no notices, no source offer, no identifiable revision) is now met on this origin. What is **not** settled: whether the narrator worker bundle forms a single combined work with the GPL component under GPLv3 §5(c) — with a lawyer, and `docs/local-narrator-notices.md` says so rather than implying the notices answer it. The model and voice data remain outside the repository; the publisher's Apache-2.0 declaration is unconfirmed in writing and the provenance of `voices.npz` is undocumented. Micro still exceeds Pages' per-file limit, so no hosting or chunking decision is made here. No public assets, hosting provision, push or native build occurred, and no license bypass.
